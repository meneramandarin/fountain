How to think about the database

The database has four layers. The raw scrape source is registered in sources. Each source row is mapped into canonical entities such as organizations, locations, practitioners, or documents. Supporting tables add treatments, prices, reviews, images, tags, and provenance. Finally, search_index is rebuilt from those canonical rows for the app.

Important edge cases and gotchas

Polymorphic links are intentional

source_records, entity_tags, and images use entity_type plus entity_id. There is no single foreign key because the row may point at organization, location, practitioner, document, or service_area.

One listing can create two provenance rows

A normal clinic listing creates a source_records row for the deduped organization and another for the specific location. This is why source_records is larger than the number of clinics.

Clinic vs organization

organizations are provider brands or parent businesses. locations are physical or listable clinic/place rows. A one-location clinic usually has one organization and one location; a chain can have one organization with many locations.

Prices live in two places

locations.price_text is source-level price text or tier text, such as $$. offerings.price_amount and price_currency are structured prices for a specific service. Only 917 offerings currently have structured prices.

Mapped and unmapped offerings both stay

offerings.raw_name always keeps the source wording. If the term maps to the taxonomy, treatment_id points to treatments. If not, treatment_id is NULL and the term is counted in unmapped_terms for future cleanup.

Reviews are location-scoped

reviews attaches only to locations. Practitioner-source reviews were skipped during canonical build because the current review schema has no practitioner review table.

Comments are reviews here

If a source exposes comments, testimonials, review bodies, reviewer names, ratings, or dates, they land in reviews when they can be attached to a clinic/location.

Images can point at different entity types

images.entity_type tells you whether the image belongs to a location, practitioner, or organization. image_url is the original URL. local_path points to downloaded media when present; the media folder itself is ignored by Git.

Documents are searchable but not clinics

PDF and government-directory pages become documents. They are in source_records, tagged through entity_tags, and indexed in search_index, but they do not become locations.

Service areas have no core table

service_area rows are source-only records from service-area style sources. They exist in source_records and entity_tags, but there is no service_areas table yet.

Search index is disposable

search_index is an FTS5 table rebuilt from locations, practitioners, and documents. Do not edit it by hand. If canonical facts change, rebuild it with data_pipeline/build_canonical.py.

Country display names are normalized

country_code keeps the ISO-like short code for filters. country_name is the full display value, such as South Korea or United States.

How common things are represented

A clinic listing

A scraped clinic becomes one deduped organization and one location. The same raw listing usually creates two source_records rows. It may also create offerings, images, reviews, and tags.

source listing sources organizations locations source_records x2 offerings images reviews entity_tags

A procedure with a price

A specific procedure is an offerings row. The raw source text is always stored as raw_name. If the procedure is recognized, treatment_id links to a canonical treatment. Price fields are only filled when the source exposed a parseable amount/currency.

Example: a source offer named "Restylane Fillers with NASHA Technology for Natural Appearance" maps to Dermal fillers with price_amount=450 and price_currency=USD.

A doctor

Doctors are practitioners. Their tags and images attach through polymorphic tables. When a doctor can be linked to a clinic or practice, affiliations connects them. The current canonical schema does not store doctor-specific reviews.

A review, testimonial, or comment

Reviews attach to locations. The table keeps reviewer, rating, date, body, and source. Some ratings and reviewer names may still be JSON strings if the source published structured schema.org markup.

A PDF page or government directory page

These are documents, not clinics. They keep raw extracted text and can be searched. Mentioned treatments become document tags like mentioned_treatment.

A source-only service area

Service areas currently have no dedicated table. They exist as source_records.entity_type='service_area' and tags such as service_area_city and service_area_service.

Scroll clinics with parent organization

SELECT l.id, l.name, o.canonical_name AS organization,
       l.locality, l.region, l.country_name,
       l.website, l.rating, l.review_count
FROM locations l
LEFT JOIN organizations o ON o.id = l.org_id
ORDER BY l.country_name, l.locality, l.name
LIMIT 100;

See offerings and prices for one clinic

SELECT l.name AS clinic,
       o.raw_name,
       t.canonical_name AS mapped_treatment,
       o.price_amount,
       o.price_currency,
       o.source_offer_url
FROM offerings o
JOIN locations l ON l.id = o.location_id
LEFT JOIN treatments t ON t.id = o.treatment_id
WHERE l.id = 1787
ORDER BY o.price_amount IS NULL, o.raw_name;

Trace source provenance for a clinic

SELECT s.slug, s.name AS source_name,
       sr.entity_type, sr.entity_id,
       sr.source_listing_id, sr.source_url
FROM source_records sr
JOIN sources s ON s.id = sr.source_id
WHERE sr.entity_type = 'location'
  AND sr.entity_id = 1787;

Reviews and comments for a clinic

SELECT l.name AS clinic, s.slug AS source,
       r.reviewer, r.rating, r.review_date, r.body
FROM reviews r
JOIN locations l ON l.id = r.location_id
LEFT JOIN sources s ON s.id = r.source_id
WHERE r.location_id = 1788
LIMIT 50;

Images attached to any entity

SELECT entity_type, entity_id, image_url, local_path, alt
FROM images
WHERE entity_type = 'location'
  AND entity_id = 1787
LIMIT 20;

Tags/facets on a clinic

SELECT t.facet, t.value
FROM entity_tags et
JOIN tags t ON t.id = et.tag_id
WHERE et.entity_type = 'location'
  AND et.entity_id = 1787
ORDER BY t.facet, t.value;

Doctor affiliations

SELECT p.full_name, p.primary_specialty,
       l.name AS clinic, l.locality, l.country_name,
       o.canonical_name AS organization,
       a.role
FROM affiliations a
JOIN practitioners p ON p.id = a.practitioner_id
LEFT JOIN locations l ON l.id = a.location_id
LEFT JOIN organizations o ON o.id = a.org_id
ORDER BY p.full_name
LIMIT 100;

Unmapped procedure cleanup queue

SELECT term, source_slug, occurrences
FROM unmapped_terms
ORDER BY occurrences DESC, lower(term)
LIMIT 100;

Document pages and mentioned treatments

SELECT d.title, d.page_number, s.slug AS source,
       t.value AS mentioned_treatment,
       substr(d.raw_text, 1, 180) AS text_preview
FROM documents d
JOIN sources s ON s.id = d.source_id
LEFT JOIN entity_tags et
  ON et.entity_type = 'document' AND et.entity_id = d.id
LEFT JOIN tags t
  ON t.id = et.tag_id AND t.facet = 'mentioned_treatment'
ORDER BY s.slug, d.page_number
LIMIT 100;
