TAXONOMY PRESENTATION CLASSIFICATION

Treatment aliases remain ingestion and matching data in
fountain_raw.treatment_aliases. Consumer display behavior lives separately in
fountain.treatment_term_presentations. The classifier never deletes aliases,
deletes treatments, or changes offerings.treatment_id.

Display policy

- format_variant and equivalent: show the clinic source term only.
- brand and subtype: show source term with canonical context.
- broader_match: show the canonical term only when auto-approved.
- compound, suspect, low-confidence, or invalid: keep the source-only default
  and set review_status to needs_review.
- The application consumes only auto_approved and human_approved rows.

Incremental workflow

Preview new aliases:

  npm run taxonomy:present -- --dry-run

Classify pending aliases with a run budget:

  npm run taxonomy:present -- --model openai/gpt-4o-mini \
    --batch-size 40 --concurrency 6 --budget 2 --apply

The query is pending-only, keyed by (treatment_id, term_normalized). Existing
classifications are not sent to OpenRouter again. Any alias added later is
picked up by the next run. Human review decisions are preserved by upserts.
OpenRouter calls use the taxonomy_presentation call type in
fountain_ops.external_calls.

Mapping corrections are a separate audited taxonomy change. Presentation
classification alone never remaps an offering.
